# Discord UX for subscription management

Slash-command surface is a single **`/jobs`** top-level command with subcommands (`subscribe`, `list`, `unsubscribe`, `config`) built via discord.js v14 `SlashCommandBuilder.addSubcommand`; subcommands keep the global namespace clean and permission scoping contained. `/jobs subscribe` takes required `source` (`linkedin|arbeitnow`, autocomplete) + `keywords`, optional `location`/`distance`/`channel`/`filters` (JSON); `/jobs list` optional `channel`; `/jobs unsubscribe <id>` autocompletes existing ids; `/jobs config` manages retention/poll knobs.

Access is gated to **`ManageGuild` (admin-only)** for all `/jobs` subcommands on MVP (subscriptions are channel-wide and affect every member); non-admins get an ephemeral "ManageGuild required" error. All management actions reply **ephemeral** (`deferReply({ ephemeral: true })`) with a confirmation embed summarizing active state — avoiding channel spam; the only **public** embeds are delivered JobPostings (ADRs 0003/0004). Permission may later relax to allow non-admin `/jobs list` when a per-guild flag exists.

**DM usage**: `/jobs` is registered with interaction contexts (`Guild`, `BotDM`, `PrivateChannel`) and integration types (`GuildInstall`, `UserInstall`), so it works in bot DMs. There is no guild membership in DMs, so the `ManageGuild` gate does not apply — the DM owner is authorized and can only touch their own DM-scoped subscriptions (scoped to a synthetic `dm:<userId>` guild, ADR-0003). The `channel` option is guild-only and ignored in DMs (delivery always goes to the DM channel); `poll_interval_minutes` is a global singleton and can only be changed from a server, while `retention_days` applies to the caller's DM subscriptions.

A delivered job is a **single rich embed, no detail fetch**: title `Position @ Company` linking the stable `jobs/view/...-{id}` URL, fields `Location`, `Posted` (relative), `Salary` (when present), optional `Easy Apply`, thumbnail = company logo, color = guild accent, footer `Kappa · LinkedIn · N ago`. Enrichment via `/jobs-guest/jobs/api/jobPosting/{id}` is deferred — an extra request per job per subscription would consume the LinkedIn budget (research-01/02) for marginal card value; click-through surfaces full detail.
