# Subscription data model: 5-table normalized hybrid on Neon

For job subscriptions on Neon + Drizzle (ADR-0001/0002, research-01/04), we use a **5-table normalized** schema: `guilds` (snowflake `text` PK), `channels` (FK guild), `subscriptions` (FK guild+channel), `seen_jobs` (FK subscription), `bot_config` singleton (`smallint PK CHECK(id=1)`). Snowflakes are `text` (Discord snowflakes exceed JS safe int); `subscriptions.id` is `serial`. All FKs use `onDelete:cascade` so `guildDelete`/`channelDelete` events cleanly cascade to `subscriptions` → `seen_jobs`.

Filter representation is **hybrid**: first-class columns for stable indexed fields (`keywords`, `location`, `geo_id`, `distance`) plus `filters jsonb` for remaining/variant LinkedIn params (`f_TPR`, `f_WT`, `f_E`, `f_JT`, `f_SB2`, `f_C`, `f_AL`, etc. from research-01) and future Arbeitnow/Remotive fields. A `GIN` index on `filters` supports ad-hoc queries (e.g. `filters->>'f_WT'`), keeping hot-path columns sargable while tolerating LinkedIn's announced filter retirement (Help a6889044, Sept 2026).

Deduplication is **per-subscription**: `seen_jobs` composite unique `(subscription_id, source, external_id)` where `external_id` is LinkedIn's numeric `urn:li:jobPosting:{id}` (research-01 stable key, not transient `href` trackingId/position) or adapter-normalized ID; `source` distinguishes `linkedin`|`arbeitnow`|… . Insert uses `ON CONFLICT DO NOTHING` before Discord delivery, preventing double-send on retry without coupling subscriptions globally. Retention is `retention_days` on `subscriptions` (default 30, nullable for infinite), enforced by application cron `DELETE ... WHERE first_seen_at < now() - interval` (Neon has no native TTL); 30 days matches LinkedIn's `f_TPR` max window and documents possible re-delivery after expiry.
